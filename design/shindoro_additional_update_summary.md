# 1. 开局页面新增：每名角色三套预设卡组

## 1.1 功能目标

开局页面中，每名角色不再只有一套默认卡组，而是提供 **3 套预设卡组**，让玩家在开始对局前选择不同打法。

建议开局流程改为：

```md
选择角色
↓
选择预设卡组
↓
选择天赋
↓
开始对局
```

每套预设卡组应显示：

```md
- 卡组名
- 推荐难度
- 对局速度
- 核心关键词
- 代表卡
- 推荐天赋
- 简短说明
- 选择此卡组按钮
```

---

## 1.2 预设卡组数据结构建议

```ts
interface StarterDeckPreset {
  id: string;
  characterId: string;

  tags: string[];
```

# 2. 卡组构筑与保存反馈修正

## 2.1 当前问题

点击“构筑卡组”或“保存卡组”后，界面没有反馈。

玩家无法判断：

```md
- 是否点击成功
- 是否正在保存
- 是否保存失败
- 卡组是否合法
- 是否跳转失败
- 是否写入 localStorage 失败
```

该问题应视为 UI / UX bug。

---

## 2.2 修改目标

所有卡组相关按钮点击后必须给出明确反馈。

包括：

```md
- 构筑卡组按钮
- 保存卡组按钮
- 删除卡组按钮
- 复制卡组按钮
- 使用该卡组按钮
```

不能出现点击后无任何 UI 变化的情况。

---

## 2.3 点击“构筑卡组”反馈

成功进入构筑页前，显示：

```txt
正在进入卡组构筑……
```

如果跳转失败，显示：

```txt
无法进入卡组构筑，请稍后重试。
```

---

## 2.4 点击“保存卡组”反馈

点击保存后必须执行：

```md
1. 显示保存中状态。
2. 校验卡组是否合法。
3. 保存成功时显示成功提示。
4. 保存失败时显示失败原因。
5. 保存期间禁用按钮，防止重复点击。
```

保存成功提示：

```txt
卡组「卡组名」保存成功。
```

保存失败提示示例：

```txt
保存失败：主卡组必须为 50 张，当前为 47 张。
```

```txt
保存失败：「余烬狼」最多只能放 3 张。
```

```txt
保存失败：请先选择角色。
```

```txt
保存失败：无法写入本地存储。
```

```txt
保存失败：发生未知错误，请稍后重试。
```

---

## 2.5 Toast 提示组件

建议新增全局 Toast 组件。

类型：

```md
success：保存成功，蓝绿光效
error：保存失败，红紫光效
warning：警告，金色光效
info：普通提示，蓝色光效
```

风格要求：

```md
- 深蓝半透明背景
- 发光描边
- 圆角面板
- 2～3 秒后自动消失
- 与新手教学页 UI 风格一致
```

---

## 2.6 保存按钮状态

保存按钮点击后进入 loading 状态：

```txt
保存中……
```

保存期间：

```md
- 按钮禁用
- 防止重复点击
- 保存结束后恢复
```

---

## 2.7 推荐保存逻辑

```ts
async function handleSaveDeck() {
  setSaving(true);

  try {
    const result = validateDeck(currentDeck, cardPool);

    if (!result.valid) {
      showToast({
        type: "error",
        message: result.errors[0] ?? "保存失败：卡组不合法。",
      });
      return;
    }

    saveDeck(currentDeck);

    showToast({
      type: "success",
      message: `卡组「${currentDeck.name}」保存成功。`,
    });
  } catch (error) {
    console.error(error);

    showToast({
      type: "error",
      message: "保存失败：无法写入本地存储。",
    });
  } finally {
    setSaving(false);
  }
}
```

# 3. 法术伤害天赋削弱

## 3.1 问题

法术伤害天赋如果是：

```md
造成伤害的魔法卡伤害 +2
```

会导致钱陈飞扬搭配直伤法术形成过强斩杀线。

特别是：

```md
爆裂炎枪原本 4费打5。
法术伤害 +2 后变成 4费打7。
```

在 20～26 血环境中，2～3 发强化直伤配合跳脸爆发，容易无视场面直接带走对手。

---

## 3.2 修改内容

```md
## 法术专注

### 修改前

造成伤害的魔法卡伤害 +2。

### 修改后

造成伤害的魔法卡伤害 +1。
```

---

## 3.3 影响示例

| 卡牌 | 原伤害 | +2 时 | +1 后 |
|---|---:|---:|---:|
| 灼烧 | 2 | 4 | 3 |
| 爆裂炎枪 | 5 | 7 | 6 |
| 审判光束打脸 | 3 | 5 | 4 |
| 镜像之墙 | 4 | 6 | 5 |

---

## 3.4 设计意图

```md
法术流仍然有构筑价值，但不能绕过场面系统形成无解直伤斩杀。
```

如果未来法术流偏弱，应优先从专属卡牌、费用曲线或抽牌效率补强，不建议再把全局法伤天赋提高到 +2。

# 4. 钱陈飞扬跳脸伤害削弱

## 4.1 实战问题

钱陈飞扬配合法术伤害、低费疾风、陷阱与爆裂炎枪后，可能在第 4 回合左右形成过早斩杀。

典型压制线：

```md
1回合：余烬狼
2回合：陷阱处理对方随从
3回合：灼烧 + 下怪 + 跳脸满槽打6
4回合：抓到爆裂炎枪后直接打死
```

问题不是单卡过强，而是：

```md
跳脸爆发 + 法术直伤 + 低费场面 + 陷阱节奏
```

共同导致过早终结游戏。

---

## 4.2 修改内容

```md
## 钱陈飞扬平衡调整

### 修改前

跳脸10点：定点爆破
对敌方核心目标造成 6 点伤害。

Overkill13点：极限爆破
强制造成 9 点爆发伤害。

---

### 修改后

跳脸10点：定点爆破
对敌方核心目标造成 5 点伤害。

Overkill13点：极限爆破
强制造成 7 点爆发伤害。
```

---

## 4.3 暂不修改内容

```md
被动：跳脸增幅
每次增加跳脸槽时，额外再获得 1 点。
```

当前建议暂时不动被动，先观察伤害下调后的表现。

---

## 4.4 后续候选削弱

如果钱陈飞扬仍然过强，再考虑：

```md
跳脸增幅：
每回合最多触发 1 次。
```

但这属于第二刀，不建议和本次伤害削弱同时执行。

# 5. AI 拟人化世界观候选映射

| GPT | C：多 Agent 调度 / 场面滚雪球型 | 综合型主神格，工具多、适配广，适合多 Agent 铺场与全体强化。 |

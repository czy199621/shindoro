# 《神どろ》UI 改版实现说明（基于新手教学页风格）

> 目标：将当前游戏 UI 统一改造成“新手教学页”的视觉风格。本文档面向 Codex / 前端开发，作为**直接可执行的 UI 改版规范**。
>
> 核心要求：**不改玩法逻辑，只改 UI 表现与交互视觉层**。

---

## 1. 改版目标

将游戏整体视觉统一为如下风格：

- **星空 + 魔法阵 + 科技感 HUD** 的幻想卡牌界面
- 主色为 **深蓝 / 靛蓝 / 紫蓝 / 金色高光**
- 版面结构使用 **发光描边面板 + 分区卡片 + 浮雕按钮 + 轻微粒子点缀**
- 角色、卡牌、双槽、关键词、按钮等都要有统一的“神秘、精致、发光”的感觉
- 整体观感参考：
  - 二次元卡牌游戏 UI
  - 星穹感奇幻面板
  - 高级教程页 / 活动页 / 启动画面质感

### 强制约束

1. **不改规则与数据结构**，除非只是为 UI 展示新增字段。
2. **不改已有功能逻辑**，只允许做样式层包装和必要的布局调整。
3. 所有页面必须保持 **信息可读性优先**，不能为了花哨而牺牲操作性。
4. 所有关键文字必须清晰，避免过度发光导致糊字。
5. 移动端与桌面端都要可用，优先保证桌面版完整度，移动端可做纵向重排。

---

## 2. 总体视觉关键词

请将全局 UI 统一到以下关键词：

- **深邃星空背景**
- **蓝紫渐变**
- **金色标题/分隔装饰**
- **冷色发光描边**
- **半透明玻璃面板**
- **魔法阵 / 菱形 / 星芒 / 几何 HUD 元素**
- **高品质二次元卡牌游戏界面**
- **精致而不廉价，华丽但不能拥挤**

### 风格一句话总结

> 像“高级二次元卡牌游戏的新手教学页”那样，把整个游戏都做成 **星空幻想科技 UI**。

## 4. 页面背景规范

所有主页面使用统一背景策略：

### 背景层级

1. **底层**：深蓝到黑蓝的径向/线性渐变
2. **中层**：淡淡星点、粒子、流光纹理
3. **上层**：大型法阵、几何图腾、菱形装饰、弧线 HUD
4. **内容层**：半透明发光面板

### 实现要求

- 背景不能是一整张平面图糊上去，尽量拆成：
  - `background gradient`
  - `noise / stars`
  - `ornament overlay`
- 主交互区域的背景亮度必须低于面板，保证对比度
- 不要使用大面积高饱和纯蓝，避免廉价感

## 5. 面板（Panel）组件规范

### 目标效果

像教程页里的每个规则框那样：

- 深蓝半透明底
- 亮蓝描边
- 四角或边缘可加装饰角标
- 内侧有一层较浅的内边框
- 标题与内容区清晰分层

### 面板样式要求

```css
background: var(--panel-bg);
border: 1px solid rgba(130, 180, 255, 0.45);
border-radius: 16px;
box-shadow: var(--shadow-panel), var(--shadow-blue-glow);
backdrop-filter: blur(8px);
position: relative;
overflow: hidden;
```

### 面板装饰建议

- 顶部可加细金线 / 发光细线
- 四角可加小型几何装饰（菱形、角标）
- 面板标题可加编号徽记或图标
- 不要过度装饰，单个面板内部最多一层装饰线

### 统一组件命名建议

- `Panel`
- `PanelHeader`
- `PanelTitle`
- `PanelBody`
- `OrnamentCorner`

## 8. 文本与信息层级规范

### 标题层级

- H1：页面主标题（如“新手教学”“卡组构筑”“开始对局”）
- H2：模块标题（如“双槽系统”“基础规则”）
- H3：小节标题（如“护卫”“疾风”）

### 正文展示原则

- 正文统一淡白色
- 重点词（如 `20`, `50`, `10点`, `13点`, `Overkill`）使用高亮色
- 说明性内容用 `text-soft`
- 弱提示用 `text-dim`

### 列表规范

- 使用发光圆点 / 小图标替代纯黑点列表
- 列表行距充足，避免挤成说明书

## 9. 特殊系统 UI 规范

这是本游戏最重要的识别元素，必须重点重做。

---

### 9.1 双槽系统 UI

需要把 **跳脸槽 / 神抽槽** 做成全游戏统一的核心视觉模块。

#### 目标风格

参考教学页的双槽区：

- 左：蓝色 / 进攻 / 优势 / 跳脸槽
- 右：紫色 / 逆转 / 劣势 / 神抽槽
- 中间：金色分隔核心或星芒图腾

#### 具体要求

- 采用圆环槽、弧形能量条或徽记式容器
- 左右必须强烈区分颜色与图标
- 明确显示：
  - 当前数值
  - 10 点阈值
  - 13 点阈值
  - 可触发效果说明
- 当达到阈值时要有清晰发光动画
- 鼠标悬停或点击可展开说明

#### 推荐文案表现

- `10点：发动角色技能`
- `13点：发动 Overkill`
- `10点：从牌库置顶关键牌`
- `13点：从公共备牌库选择终结者`

#### 状态反馈

- 未满：暗淡流动光
- 即将达到：边缘频率更高、轻微脉冲
- 已达到：明显发光 + 提示标记 + 可点按钮

---

### 9.2 卡牌 UI

卡牌本体建议统一：

- 细边发光外框
- 深色卡面底
- 角色图/插图为视觉主体
- 数值区与类型标签采用统一风格

#### 卡牌信息区样式

- 费用：左上角发光宝石 / 徽章
- 攻击 / 生命 / 威胁值：底部角标，建议颜色区分
- 卡牌类型标签：使用小型发光胶囊
- 关键词标签：蓝 / 紫 / 金小标签

#### 场上卡牌槽位

- 空槽位也要有微弱边框与占位图案
- 鼠标 hover 时卡牌浮起并增强描边
- 可攻击状态要高亮
- 被锁定 / 不可操作要明显变暗

---

### 9.3 关键词标签 UI

对 `护卫 / 疾风 / 战吼 / 亡语 / 吸血 / 必杀` 等做统一关键词表现：

#### 推荐规范

- 使用小标签（Badge）
- 每个关键词一套固定颜色与图标

例如：

- 护卫：蓝色盾牌
- 疾风：青色风纹
- 战吼：橙金喇叭
- 亡语：紫黑骷髅
- 吸血：红紫血滴
- 必杀：金红利刃

### 展示方式

- 卡牌详情页完整展示
- 卡牌缩略状态下显示精简图标
- Hover 时弹出说明 Tooltip

---

### 9.4 弹窗 / 模态框 UI

所有弹窗（确认、卡牌详情、教学、奖励、设置）统一使用：

- 深蓝发光面板
- 标题顶部带装饰条
- 关闭按钮使用细线发光样式
- 蒙层为深蓝半透明，不用纯黑硬遮罩

#### 弹窗层级建议

1. 背景蒙层
2. 发光主面板
3. 标题与图标
4. 内容区域
5. 按钮区域

## 11. 交互动效规范

动效必须存在，但不能喧宾夺主。

### 动效原则

- 轻量
- 清晰
- 响应快
- 不拖慢操作

### 推荐动效

#### Hover

- 面板：亮度提升 3%~6%
- 按钮：上浮 1~2px + 发光增强
- 卡牌：轻微抬起 + 描边发亮

#### Click

- 按钮轻微缩放
- 卡牌点击后弹起/选中外框

#### 状态变化

- 双槽涨点：脉冲光效
- 阈值达到：一次明显闪光
- 受伤 / 回复：数值浮字 + 对应颜色闪烁
- 可行动卡牌：蓝色呼吸光

#### 弹窗出现

- 淡入 + 轻微上移 / 缩放
- 不要做过长动画，建议 `180ms ~ 260ms`

---

## 12. 响应式与适配要求

### 桌面端（优先）

- 目标宽度：`1440 / 1600 / 1920`
- 页面不应显得空
- 面板之间保留呼吸感

### 移动端

- 面板纵向堆叠
- 复杂区域允许折叠或分页
- 对局页优先保留：
  - 战场
  - 手牌
  - 回合按钮
  - 双槽

### 最低可接受

- 文字不重叠
- 主要按钮可点
- 关键系统可见

## 15. 视觉禁忌

以下风格不要出现：

1. **纯办公后台风**（灰白、扁平表格）
2. **手游廉价活动页风**（过饱和、乱描边、信息拥挤）
3. **过度未来科技风**（纯赛博，不够幻想）
4. **欧式黑金宫廷风过重**（会偏离教学页蓝紫主调）
5. **大面积纯黑背景 + 白字**（缺乏层次）
6. **按钮颜色五花八门**（应控制在金 / 蓝 / 紫体系内）

## 19. 最终目标效果

改造完成后，整个游戏应该给人的感觉是：

> **像一个已经完成美术包装的二次元原创卡牌游戏，而不是一套规则原型 UI。**

具体来说：

- 打开主界面，就像进入一个有世界观氛围的游戏
- 进入对局，双槽、卡牌、阶段、战场都有统一包装
- 进入卡组页，像在看图鉴与构筑系统
- 新手教学页与正式 UI 没有割裂感

如果出现“只有教学页好看，正式游戏还是像开发工具”的情况，则视为改造失败。
